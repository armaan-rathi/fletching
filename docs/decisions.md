# Decisions log

Running log of design and tech decisions, especially anything that deviates from `fletching_design.md`.

## 2026-11-06 — Stage 1, steps 1–2

### Tooling: command line instead of MCP (deviation)
The design doc plans for Godot and Blender MCP servers. None are connected; with the user's OK, both are
driven from the command line instead:
- Godot: `--headless --import`, `--headless -s <tool script>` for generation/checks, and a short windowed run
  of `tools/screenshot.gd` for visual captures (needs a GPU, so a window flashes briefly).
- Blender: `Blender -b --python <script>`; renders/exports replace the MCP `look` command.
Difference to watch: no live Blender viewport, so model reviews are done with scripted renders.

### Project setup
- Input actions in `project.godot`, generated by `tools/setup_project.gd` (re-runnable). All events use
  device -1 (any device) for Stage 1; per-player device mapping is Stage 3.
- Gamepad shoot = right trigger (axis), dash = A/Cross (button 0), pause = Start.
- Mouse aim is handled in code (cursor → ground-plane ray), not as an input action.
- Window 1600×900, stretch `canvas_items` / `expand`. MSAA 2× for outline quality.
- `scenes/props/` added to the structure for prop wrapper scenes (KayKit model + collision), used from step 4.
- `tools/` added for generator / check scripts (not shipped).
- Tunables: `scripts/tuning.gd` (`class_name Tuning`) + `data/tuning.tres`; access with `Tuning.get_default()`.
  Bounce spec and camera margins/pitch are in there too.
- License files: the packs ship without license files; all three are CC0 (confirmed by the user) and are
  credited in `CREDITS.md`. Nothing inside `assets/third_party/` was added or changed.

### Look
- **Outline method: inverted hull** (`assets/shaders/outline.gdshader`) as the `next_pass` of toon materials.
  Chosen over a screen-space post-process because it allows per-object tint (player color) and only
  outlines what we choose. Width 0.03 m (constant on screen thanks to the ortho camera). KayKit's flat-shaded
  models show tiny gaps at hard corners, which aren't noticeable at game zoom.
- **Toon lighting** lives in `toon_lighting.gdshaderinc`: 2 bands, shade = global `toon_shade_color`
  (#6B70A8, cool) × light energy, lit = warm sun color. Environment ambient is 0, tonemap linear,
  so colors stay flat and controlled. Optional thin rim light per material.
- **Hard shadows** (`soft_shadow_filter_quality = 0`): the soft filter's dithering looked noisy against flat colors.
- **Key light**: warm #FFE6B0 from the front-left (rotation −55°, −70°) so the camera-facing sides are lit;
  shadows fall right and slightly back.
- **Third-party props**: `scripts/toon_prop.gd` instances a KayKit model and overrides its materials with
  `assets/materials/kaykit_forest_toon.tres` (toon + outline, using KayKit's gradient atlas as albedo).
- **Background**: `ground.gdshader` paints the clearing (rounded rect, wobbly edge, sparse moss patches),
  a forest-floor dirt band, then fades to dark undergrowth. Tall trees on the back and sides only;
  the front edge (nearest the camera) uses low bushes and rocks so nothing covers the arena.
- **Camera**: `scripts/arena_camera.gd`, orthographic, fits the ortho size to the arena for the current aspect
  ratio, with a top band reserved for score UI via `v_offset`. Look test supports keys 1/2/3 for 50/55/60°.

### Palette (sampled from KayKit Forest `forest_texture.png`)
KayKit's atlas is three vertical gradients. Samples (top → bottom):
- Foliage: #85C23F #69AF3D #46973B #248039 #086D37
- Bark (orange in the source): #EF7B36 #DC7134 #C36532 #A04A2A #843424
- Rock: #AAB8BE #9BA8AE #828C91 #697175 #596064

Result: the doc's draft palette already sits well with the foliage band, so it is kept as is:
grass #8DBF5A, moss #4F7F3A, dirt #9C7A52, bark #6B4A33, deep foliage #2F5D3A, sun #FFE6B0,
outline #2A2233, player colors #FF5A5A / #4DA6FF / #FFD23F / #B57BFF. Shade tint is #6B70A8 (a lighter
version of the draft's #4A4E7A, because it multiplies the albedo rather than replacing it).
KayKit's orange bark is pulled toward #6B4A33 with a per-band tint in the toon material (`band_tint_1`).

### Approved

### Pipeline
- Blender models are generated by scripts in `tools/blender/` (re-runnable; `.blend` sources saved to
  `assets/*/source/`). `source/` folders have a `.gdignore` so Godot doesn't try to import `.blend` files

- Godot scenes for Stage 1 are generated by `tools/build_stage1.gd` (extends the look-test builder, so the test
  map shares the approved environment, light, camera, ground and border).
- **`Fx` is a static class, not an autoload** (deviation: autoloads aren't ready when command-line tool scripts
  compile game scripts). Same API: `Fx.shake()`, `Fx.hit_stop()`, `Fx.dust()`, `Fx.impact()`, `Fx.poof()`.
  The MatchManager autoload (Stage 3) will need the same care; tool scripts wait one frame before loading.
- `tools/sim_playtest.gd` drives inputs on the test map and checks movement, dash, draw/fire, sticking, pickup,
  auto-return and mouse aim (21 checks), saving screenshots. Run it after gameplay changes.

### Look fixes
- **Global shader colors are not sRGB-decoded** by Godot, so `toon_outline_color` rendered as a light purple-gray.
  The shaders now decode them; outlines are the intended near-black #2A2233. To keep the approved shading
  identical, `toon_shade_color` is now stored as #ACAFD3 (renders the same as before).
- **Canopy fade** (from the doc's Occlusion notes): trees screen-door dither their canopy (instance uniform
  `canopy_fade`, `scripts/canopy_fader.gd`) while a bird or a stuck arrow is behind it on screen. Without it, arrows
  stuck in the central tree were completely hidden at 55°. The canopy shadow dithers too (acceptable for now).
- **X-ray silhouette**: the bird's body has a third material pass (`xray.gdshader`) drawing a player-colored
  silhouette only where it's occluded.

### Bird v0
- Egg body (body + belly slots), procedural anime eyes (`eye.gdshader` on planar UVs), cone beak, wings, tail,
  legs, feet; 12-bone shared skeleton with the doc's names; 1,698 tris. Imports facing +Z; the wrapper turns it 180°.
- Wing bones are posed procedurally (flap on hops, reach forward while drawing). Keyframed animations are Stage 2.
- Colors are exports on `BirdModel` for now (sparrow-ish browns); BirdData replaces them in Stage 2.

### Bow and arrows (deviations / additions)
- **Bow is not on a `BoneAttachment3D` to `hand_R`** (deviation). It's positioned procedurally: slung across the
  back when idle, held flat in front while drawing. Held flat so the arc and string pull read from the top-down
  camera, and centered so arrows leave from the bird's center (aim matches the aim line). Can move onto the bone
  when Stage 2 keyframes a proper draw pose.
- **Arrow range from gravity**: arrows fly at `arrow_height` (0.55 m) with light gravity (`arrow_gravity` 2.4),
  giving ~10 m range at min charge and ~20 m at full. Out of range they land and lie on the ground.
- **Mouse aim** projects the cursor onto the arrow-flight plane (y = 0.55), not y = 0, so arrows pass visually
  under the cursor.
- **Aim sources** (agreed): while drawing, whichever of mouse / move input / right stick was touched last aims.
  When not drawing, the bird faces its move direction; right stick overrides; an idle keyboard bird faces the
  cursor for 1.5 s after the mouse moves.
- **Aim line** on the ground shows the predicted path and stops where the arrow would stick.
- **Charge ring** fills around the bird; a flash and sparkle mark full charge.
- **Quiver** is shown on the bird (small arrows on its back) plus a debug HUD count.
- Shoot with an empty quiver does a little flutter (wing slap is Stage 3).
- Holding shoot through a dash starts drawing as soon as the dash ends.
- Dash cooldown counts from the end of the dash.
- New tunables: arrow height/gravity/penetration/max flight/pickup radius, recoil speed/hop, shake amounts,
  `hitstop_arrow_stick` (0.04 s on full-charge sticks; set 0 to disable), punch-zoom amount.

### Test map
- Same border as the look test; invisible box walls (layers world + arrow_stickable) just inside the border
  bushes, so arrows stick "in the bushes". Central KayKit `Tree_1_A` wrapped in `scenes/props/tree_central.tscn`
  with a 0.36 m trunk cylinder. Debug HUD: F1 help, F5 reload `tuning.tres` live, R restart.

## 2026-11-07 — Design doc update, lighting pass, shape exploration

### Camera and map
- Camera pitch lowered 55° → **50°** (`tuning.camera_pitch`), per user.
- Central tree is now **KayKit `Tree_4_A`** (slim trunk, conical canopy from ~1 m to ~4.9 m). Trunk collision
  radius 0.22 m; canopy fader tuned to center 2.7 m / radius 1.5 m.

### Lighting pass (test map)
1. Clearing patches are now lighter/warmer than the grass (#98BC5A, #A8C864), not darker, so they don't read as shadows.
2. Cast shadows are separated from form shading: `toon_cast_shadow_color` (#9AA0DC, multiplicative) plus
   `toon_cast_shadow_lift` (additive #4A4E7A at 35%, the doc's shadow tint), because multiplying green grass by
   blue can't make it look cool. Hard shadow filter kept; shadow map 8192 over 40 m for crisper edges.
3. Bird ground shadow: an invisible **shadow-only disc** just above the ground under each bird. It gets exactly the
   same crisp, cool cast-shadow look as the trees and stays on the ground while the bird hops (shrinks slightly
   in the air). Bird meshes no longer cast their own shadows.
4. Border fade: every toon surface and the ground darken (35%) and desaturate (35%) with distance outside the
   arena (`border_fade.gdshaderinc`, globals `arena_half_size`, `border_darken`, `border_desaturate`,
   `border_fade_distance`), plus a subtle screen vignette. The clearing is the brightest area.
5. Birds get a stronger rim light that also shows on the shaded side (`rim_in_shade`).
6. Tonemapping: **Linear vs AgX** comparison in `docs/screenshots/lighting/`. AgX dulls the flat palette
   (grass goes olive); recommendation is to stay on Linear. Pending the user's call.
- Bug fixed: the x-ray silhouette was tinting the bird's own eyes/beak (they occlude the body). It now ignores
  occluders within ~0.4 m.

### Bird base model update (doc revision)
- Doc now specifies chibi proportions (big separate head on a neck, pear torso, chunky split beak, big 3-toed
  feet), a 14-bone skeleton adding `neck` and `beak_lower`, eye patch meshes with an expression texture atlas,
  head tracking, body shape keys, and a 1.2–2k tri budget.
- Order of work: since the base bird is being rebuilt after the shape pick, `beak_lower`, the split beak and
  eye patches go into that rebuild rather than being retrofitted onto the v0 egg.
- **Shape exploration** (`tools/blender/shape_exploration.py`, renders via `tools/render_exploration.gd`):
  40/50/60% head ratios × eagle-style and owl-style heads, rendered at in-game scale from the 50° game camera
  (1:1 crop and 3× zoom) and from the front. In `docs/screenshots/shape_exploration/`. Eyes sit above the head's
  midline and tilt up so faces read from the game camera.
- Exploration meshes are 3.1–3.4k tris (over budget); the rebuild will cut segments (toes, wing tips) to fit 2k.

### Testing
- `tools/sim_playtest.gd -- <dir> quick` runs a short smoke test (walk, dash, shot into the tree, pickup).
- Windowed sim runs can flake if the Godot window loses focus mid-run (Godot releases held inputs on focus loss).

## 2026-11-07 — Stage 3: combat and local multiplayer

### Open questions answered by the user
- **Q1 Curve feel:** curving starts immediately on release, gentler 120°/s at full sideways input, 0.6 s window
  (`curve_max_turn_rate`, `curve_window`). Steering is the shooter's move input relative to the arrow's flight
  direction (so it also moves the bird sideways, as the doc intends).
- **Q6 Wing slap:** 1.3 m range, 120° frontal arc, 0.5 s cooldown; the slapper is rooted 0.25 s and the hit lands
  0.08 s in (`slap_*` tunables). One-hit KO, respects dash i-frames.
- **Q7 Keyboard players:** one keyboard(+mouse) player; everyone else on gamepads.
- **Q8 CPU difficulty:** Easy, Normal and Hard (`cpu_profiles` in tuning).

### Hits and KOs
- Arrows raycast against bird hitboxes (layer 3) as well as the world. The shooter's hitbox is always excluded
  (no self-hits). A dashing bird inside its i-frame window is passed through.
- **Arrows pierce** (my call): after knocking a bird out, an arrow keeps flying and can hit more birds or stick
  behind them. KO'd birds' hitboxes are disabled.
- KO: hit-stop (`hitstop_ko`), shake, punch-zoom, a chunky toon-shaded feather burst in the bird's colors
  (`Fx.feathers`), knockback along the hit with a spin, the KO clip (it falls backwards = along the hit), KO face +
  dizzy stars. The body stays limp on the ground until the round ends. The killer gets the smug face.
- Shocked: an enemy arrow passing within `near_miss_distance` (0.9 m). Annoyed: firing your last arrow.

### Players and devices
- `PlayerInput` now reads one player's device(s) only, using the input map's bindings filtered by device
  (keyboard/mouse vs. a specific gamepad), so remapping still works. Mouse aim only for the keyboard player.
- `MatchManager` autoload (doc): players {slot, name, color, cpu, difficulty, keyboard, joypad, bird, variant},
  rounds_to_win, scores, stats (KOs, arrows, deaths). Until Stage 4's menus, `setup_quick_play()` builds the match
  from connected devices: P1 = keyboard (+ pad 0 unless "split"), one player per extra pad, then CPU fill to 4,
  each a different bird. Debug keys: J split devices, C CPU count, K CPU difficulty, R restart.
  Tool scripts reach the autoload with `root.get_node("MatchManager")` (globals aren't known when they compile).

### Rounds
- `RoundController` (in the arena): spawns from `MatchManager.players` at 4 corner spawn points (shuffled each
  round), 1.5 s frozen countdown, last bird standing wins the round (0.9 s grace for simultaneous KOs; nobody
  left = draw, no point), winner plays the victory clip with the happy face, 2.5 s scoreboard, first to
  `rounds_to_win` (3) wins the match; losers sad, winner happy, results table (wins, KOs, arrows), R rematch.
  A single player runs as practice (no rounds). `MatchHud` is a placeholder UI for Stage 4 to replace.
- `Bird.pose_override` holds a looping clip (victory) over idle. This also fixed the Stage 2 G-key previews
  of victory/KO, which were being overwritten by idle on the next frame.

### CPU birds
- `CpuInput` drives a Bird through the same interface as a human: nearest-enemy targeting, keeps ~65% of its
  range, strafes around cover for line of sight, draws for a random charge time with lead and per-shot aim error,
  dodge-dashes incoming arrows (chance + reaction delay), collects stuck arrows when empty, slaps when close.
  Hard CPUs curve shots around cover. CPUs don't show an aim line.
- In a 4-CPU test match the Hard CPU won 3–1 (7 KOs from 29 arrows); rounds lasted ~4–15 s of game time.

### Known limits
- A bird hidden behind *another bird* gets no x-ray silhouette (shared stencil bit).
- Stage 4 replaces the quick-play setup and placeholder match UI with character select, settings and screens.

## Melee rework: separate button, stun, arrow bat (user request)
This overrides the design doc's "Melee = same as Shoot when out of arrows" and "wing slap = one-hit KO" (Controls,
Combat). Open question 6's range, arc and cooldown are kept.
- **Own button:** right mouse / F on keyboard; RB / X on pad (action `melee`). It works with or without arrows and
  cancels a draw. Shoot with an empty quiver now does nothing (flutter + annoyed face).
- **Slap = stun, not KO:** birds in front (1.3 m, 120°) are dazed for `stun_time` 1.0 s.
  - While dazed they can't move, shoot, dash or melee. They get dizzy stars and a "stunned" expression.
  - They're shoved 4 m/s along the hit, and they can still be shot (melee → point-blank shot is the combo).
  - After a stun there's `stun_immunity` 0.6 s before they can be stunned again (no stun-lock).
  - Mid-dash i-frames still dodge it.
- **Arrow bat (parry):** for the first `parry_window` 0.08 s of the swing, an arrow that meets the wing is batted away.
  - The wing covers up to `parry_reach` 0.9 m, in front (`parry_arc` 150°).
  - The arrow's path is checked across the whole frame, so fast arrows can't skip through the window.
  - **Direction:** the arrow is mirrored about the contact direction (bird → contact point). Head-on goes straight
    back; a glancing hit skims off sideways. It keeps its speed.
  - **Ownership:** the batted arrow stays live and now belongs to the batter (it can KO its own shooter; the batter
    gets the KO), but it still returns to the original shooter's quiver (`Arrow.quiver_owner`). Curve steering ends.
  - **Cost:** the batter is shoved back (`parry_knockback` 9 m/s, about 0.75 m) and can't melee for `parry_cooldown`
    1.0 s. It also gets a short hit-stop, sparks and a smug face.
  - A white swoosh arc shows each swing so the timing is readable.
- **Measured timing window** (press time before impact that still bats): about 40–130 ms against the slowest arrows
  (14 m/s) and 30–100 ms against the fastest (28 m/s), so roughly 90 / 70 ms wide. First pass was 0.12 s / 1.0 m
  (about 160 / 120 ms), tightened to fit "pretty tight".
- **CPU:**
  - Slaps (stuns) enemies that get within reach (chance per profile: easy 0.3, normal 0.6, hard 0.9), then takes a
    quick point-blank shot at the dazed bird.
  - Tries to bat incoming arrows (easy 0, normal 0.12, hard 0.3) with timing jitter (0.1 / 0.06 / 0.03 s).
  - When empty, it no longer charges in to slap; it goes for arrows.
- **Balance check** (6 CPU matches, power-ups on): Hard 15 rounds, the 2 Normals 17, Easy 2 (about the same as
  before). 29 arrows batted in 36 rounds, only 2 stuns (CPUs keep their distance). The first try, with hard parry
  0.5, was too strong (Hard won 5/6 matches).
- **Tests:** `tools/sim_melee.gd` (12 checks). sim_stage3's slap check now expects a stun.

- **Rendering fixes found during the pass:**
  - **Per-vertex outline width:** stored in UV2.x. The bird outline material (`vertex_width`, set only in

    and toe tips taper to crisp points, and parts that start buried in another part (beaks, nape feathers, tufts,
    tail bases) have near-zero width there, so their hull no longer pokes dark lines through faces and heads.
  - **Eyes were decagons:** the eye filled its 10-sided patch to the edge. Patches are now 20-sided with a
    lid-coloured margin ring, so the shader draws a smooth circle. Eye patches also use the head's sphere normals.
  - **Lid lighting:** the eye material now gets the same near-white lighting (`neutral_light` / `shade_lighten`)
    and `rim_in_shade` as bird surfaces. Pale faces (eagle, swan, owl disc) lost their darker "eye sockets".
  - **Twisted beak tips and nape feathers:** blades whose path turns toward their thin axis twisted, which showed
    as dark star spikes. Those now build their section from a fixed wide axis (`side=X`).
  - **Owl disc:** its offset from the head scales with surface steepness, so the head no longer pokes through at
    the sides.

## KO twitch fix
The user still saw birds twitch after dying. A frame-by-frame probe found three causes:
1. **One-shot clip hijack:** the KO expression (or a near-miss "shocked" just before the hit) started the squawk
   one-shot, which replaced the limp `ko` clip for the whole fall. The limp pose only began about 0.44 s in, after
   landing, so the wings and legs flopped out (up to ~9° per frame) on the ground.
   Fix: `BirdModel.play_state("ko")` cancels any one-shot, `play_once` is ignored while KO'd, and the KO scream is
   only the beak pop.
2. **Whippy spin:** the ease-out started at ~2,700°/s (40°+ per physics tick). Now a sine ease over
   `ko_flop_turns` 0.5 turns. The landing squash `ko_land_squash` went from 0.3 to 0.15.
3. **60 Hz stepping:** the tumble was computed in `_physics_process` (60 Hz) while rendering at 80–120 fps, so it
   visibly stepped. The tumble visuals now update in `Bird._process` at render rate (`_ko_visual`); the slide stays
   in physics.

`tools/ko_check.gd` now kills the bird mid-squawk and requires: the first clip after the KO is `ko`, and after
the flop and squash no bone moves (< 0.5 mm per frame). With the old code it fails (squawk first, 6 mm per frame).
Other birds' movement still updates at 60 Hz without physics interpolation; it's on the testing list for
high-refresh displays.

## Shrike (lob shot) (user request)
A new attack: fire an arrow straight up. It hangs out of sight while the shooter steers where it lands, then drops
straight down. Use it to get over cover or to set a trap.
- **Controls:** action `shrike`: Q or middle mouse; LT or Y on pad. Hold to charge like a shot (the bow tilts up and
  there's no aim line), release to launch. The empty-quiver click applies.
- **Flight:**
  - Rises for `shrike_rise_time` 0.28 s to `shrike_height` 9 m.
  - Hangs out of sight for `shrike_hang_min..max` 0.7–1.3 s (charge-scaled).
  - Drops at `shrike_fall_speed` 26 m/s (~0.35 s).
- **Landing spot:** where the shooter stood, unless steered. The shooter's move input moves it at
  `shrike_steer_speed` 4 m/s until the drop starts (then it's locked; it's also clamped to the arena). That gives
  about 4–6.3 m of steering. A ring in the shooter's colour marks the spot and shrinks as it nears; it's fully
  opaque while locked.
- **Impact:**
  - It KOs any bird it passes through (never the shooter), smashes eggs, and sticks upright in the ground or into
    the top of cover. Then it's a normal pickup with the normal return.
  - A falling shrike can't be batted away.
  - Eggsplosive shrikes explode on landing. Trifecta drops three across (`shrike_trifecta_offset` 1.1 m); the side
    ones poof.
  - Sounds: the shot plus a pitched-down whoosh on the drop.
- **CPU:** with no line of sight and the target within `shrike_range` 9 m, a CPU lobs a shrike (chance per profile:
  easy 0.15, normal 0.3, hard 0.45) and steers the landing onto the target's predicted spot. CPUs also dash out of
  an enemy shrike's ring (their dodge chance and reaction).
- **Balance check** (6 CPU matches, power-ups on): Hard won 15 of 30 rounds (was ~42%), the two Normals 12 and
  Easy 3. Worth watching.
- **Tests:** `tools/sim_shrike.gd` (13 checks).

## Art style exploration (user request)
A live style switcher for exploring alternative looks. Nothing is rebuilt: the styles live in the shared shaders
behind global uniforms, plus two scene passes and one post pass.
- **Keys (arenas):**
  - U cycles both layers together (Shift goes back).
  - Y cycles the characters' style only, P the environment's only, so hybrids can be tested.
  - O toggles the shown styles' option: anime FX extras (on by default) and watercolor pencil lines (off by
    default).
  - I toggles tilt-shift.
  - A toast names the style(s). `scripts/art_style.gd` (static `ArtStyle`) keeps the styles across scenes; the
    DebugHud re-applies them on scene load (a reloaded scene brings a fresh Environment).
- **Two layers:**
  - Globals `art_style_char` / `art_style_env` (+ `art_style_opts`). Shaders that `#define AS_CHARACTER` before
    the include read the character one: the per-slot bird toon / outline / eye shaders, and the new
    `toon_actor` / `outline_actor` used by flying arrows. Everything else reads the environment one.
  - A macro maps the old `art_style` name to the right global, so the style code is shared.
  - Frame-level effects can't be split by layer, so they follow the environment style: paper, grain, bokashi,
    pixel palette and resolution, misregistration.
  - Stop-motion stepping applies if either layer is felt or claymation. Glow is on if either layer is anime.
- **Where it lives:**
  - `assets/shaders/art_style.gdshaderinc`: helpers (noise, hatching, halftone screens, riso ink separation,
    HSV, anime shade rule, line-from-color, clay height + derivative bump mapping) and `as_style_albedo`.
  - Branches in `toon_lighting.gdshaderinc` (all lit surfaces: birds, props, ground, water, eye lids),
    `toon_body.gdshaderinc`, `ground.gdshader` and `outline_body.gdshaderinc`.
  - **Scene passes** (`style_scene_env` / `style_scene_char`, body in `style_scene_body.gdshaderinc`):
    - Full-screen quads drawn first in the transparent pass (render priority -128). Each reads the opaque
      scene's color (with mipmaps), depth and normals.
    - They are gated by the stencil the birds already write: env = stencil 0, char = stencil != 0. Birds are
      1–4; flying arrows now write 5, which every bird's x-ray still draws over, as before.
    - Particles and x-ray silhouettes draw after them.
  - **Post pass:** `style_post.gdshader` runs on a CanvasLayer at -2: over the 3D view, under the vignette and
    every HUD/UI layer.
  - **Pixel palette:** `style_palette.gdshaderinc`, 30 colors picked from the game's palette.
  - Baseline (0) takes exactly the old code paths; a capture of it matches the previous one.
- **Per-material line colors:**
  - Outline materials now carry the color they outline (`base_color`). `ToonMaterials` gives every toon /
    character material its own outline duplicate instead of the shared one.
  - Textured forest props use `assets/materials/outline_forest.tres`, which samples the same texture.
  - The baseline ignores these values.
- **Styles:**
  1. **Field guide:**
     - Watercolour: pigment desaturation, uneven washes with paper showing through, granulation; big soft washes
       with pooled edges on the ground.
     - Warm-paper light with ink crosshatching: single in form shade, crossed in cast shadow.
     - Finer sepia ink outlines; warm paper tone and paper grain in post.
  2. **Felt stop-motion:**
     - Matte dusty colour with mottling and fibres sized to read at game zoom; soft wrap light with a fuzzy edge
       sheen.
     - Stitched outlines: dashed cream thread over a dark felt rim; soft grain and a vignette.
     - Rendering is capped at 12 fps while it's active (physics and input stay at 60 Hz). That steps the whole
       picture like real stop-motion, including the UI, and adds up to ~80 ms of display latency. Per-character
       stepping is a possible refinement.
  3. **Risograph:**
     - Fills are separated into fluorescent pink, teal and yellow ink coverage (least squares on ink absorption
       over cream paper). Each ink is posterized to none / one tint / solid and printed as its own halftone screen
       at its own angle; overprints come from the overlap.
     - A 4th ink, blue, is the line and shade plate (outlines and shade dots). Post adds slight misregistration
       and heavy grain.
     - Player colours (rings, x-ray, trails, markers, HUD) use their own materials, so they stay outside the
       palette.
     - The first try (nearest ink, 3 inks) made the grass murky. The second (full 3-ink separation) was a dot
       blizzard. Posterizing and using teal for foliage fixed both. The grass's fine tint dots are the main
       readability risk left.
  4. **Sketchbook:** a paper world with a pastel tint, graphite hatching that jitters about 8 times a second,
     graphite outlines whose width "boils" (redrawn about 8 times a second), and paper grain.
  5. **Tilt-shift:** a toggle that combines with any style. The frame's top and bottom blur out (mip-based blur
     with a few taps), with a little extra saturation for the miniature look.
  6. **Anime:**
     - **Authored shadow colors:** every material built by `ToonMaterials` gets its own `anime_shade`
       (`ToonMaterials.anime_shade()`): warm hues lean red, the rest blue-violet, more saturated and darker;
       whites get lavender. Textured props derive it in-shader with the same rule. Cast shadows use it too.
       Overriding a material's shade is one uniform.
     - **Hard cel band, sharp highlights:** a crisp specular dot on characters and props.
     - **Rim light with bloom:** the rim on the lit side goes above 1.0, and the environment's glow (HDR threshold
       1.0) blooms it. The scene's own glow settings are saved and restored.
     - **Smoothed face normals:** `BirdModel` feeds the head center every frame (instance uniform `as_face`). The
       bird toon shader bends normals within ~0.3 m toward a sphere's, so the face shades as one shape.
       `face_smooth` = 0 opts out beaks, legs, bows and quivers.
     - **Weighted outlines and inner lines:** outlines are thin on top and heavy underneath. Inner lines come from
       depth breaks and sharp normal creases in the scene pass. Birds get a finer depth threshold. Only sharp
       creases count, so feathers and grass don't turn solid.
     - **FX extras (O toggles; anime characters only):**
       - Dash speed lines (`Fx.speed_lines`).
       - Wing-slap smears: a tapered crescent in the bird's color with a dark edge, flashed for 0.12 s along the
         swing (`Fx.smear`).
       - KO impact frames: ~0.2 s real time. A black-and-white threshold, inverted for the first half, with
         radial burst lines that contrast with whatever is under them (`ArtStyle.impact_frame`, called from
         `Bird.knock_out`).
  7. **Watercolor:**
     - **Washes:** transparent pigment (paper shows through, density pooled by noise), granulation in the pigment
       and cold-press paper tooth in post.
     - **Light:** a soft terminator, and shade is a cool blue-violet glaze.
     - **White paper in highlights:** the brightest lit areas are left as bare paper, broken up by noise. This is
       strong on birds, a pale reserve on scenery, and not on the ground: its whole plane faces the sun, so it
       would go white.
     - **Scene pass:** wobbly (noise-warped) sampling, color bleeding (mip blur) and edge darkening (pigment
       pools on the darker side of every color edge).
       - Scenery gets a 3.5 px wobble with heavy bleed. Birds and arrows (character layer) get 1 px with light
         bleed, so they stay crisp.
     - **Optional pencil lines (O):** thin boiling graphite outlines. With them off, outlines are hidden and the
       edge darkening carries the shapes.
  8. **Woodblock print:**
     - **Colors and outlines:** flat ink colors in two impressions (the shade block is an indigo overprint).
       Outlines are bold sumi ink with a slight carved wobble.
     - **Wood grain:** the block's grain prints through as wavy stripes, with uneven pressure leaving paper
       showing.
     - **Post:** washi fibers, plus bokashi (soft hand-wiped gradients) in prussian blue at the top of the print
       and umber at the bottom.
  9. **3D pixel art:**
     - **Low-res render:** 3D renders at 1/3 resolution (`scaling_3d_scale`), and the post pass samples it on the
       same 3 px grid.
     - **Palette:** a limited 30-color palette from the game's colors, with a light 4×4 ordered dither.
     - **Lines and bands:** thick outlines in a darkened local color (sel-out style) that survive the low
       resolution as crisp 1-pixel lines; hard light bands; no rim.
     - **Pixel-snapped camera:** the shake moves in whole low-res pixels and the punch zoom is off, so scenery
       never shimmers.
     - **As a character style only:** the char scene pass pixelates and palettizes just the birds.
     - **Player colors:** they are in the palette, but rings get quantized like everything else.
  10. **Claymation:**
      - **Surface:** a saturated, slightly waxy plasticine color. Clay detail is derivative bump mapping from a
        height field: thumbprints (whorled ridges, a few per 35 cm cell) and soft sculpted lumps, re-sculpted
        slightly every stop-motion frame. The detail is scaled up to read at game zoom.
      - **Light:** a wide soft terminator, warm (subsurface-like) shade, soft shadows and a broad waxy sheen.
      - **Outlines:** thin creases in a darkened local color.
      - **Stepping:** shares felt's 12 fps stop-motion stepping.
  11. **Colored line art:**
      - Outlines and inner lines take the color underneath: same hue, more saturated, much darker.
      - Fills are slightly lighter and shade is softer, so the lines carry the form.
- **Known side effect (not new):** a feather particle that passes in front of a bird counts as an occluder, so
  that bird's x-ray tint shows through it for a moment. It shows up more in the captures because particles are
  frozen mid-air.
- **Performance:** `docs/style_perf.md` (`tools/style_perf.gd`). At native resolution every style and hybrid holds
  this Mac's ~80 fps cap. At 4× pixels the scene-pass styles cost the most: anime ~70, watercolor ~66, and the
  anime + watercolor hybrid ~62 fps. GPU timestamps aren't available on Metal here.
- **Captures:** `docs/screenshots/styles/` (`tools/style_shots.gd -- <dir> [name filter]`):
  - The same frozen frame in every style, plus tilt-shift on baseline and on field guide.
  - Watercolor with pencil lines, the anime FX extras, and five hybrids.
  - Sheets: `styles_overview.png`, `styles_closeup.png` and `styles_hybrids_fx.png`.
